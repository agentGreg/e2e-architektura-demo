# Karta dla IT: ustawienia Claude Code potrzebne do marketplace’u sekcji testów

Wersja 1.2 z 30.10.2026 (zmiany względem wersji 1 z 23.10 oznaczone „[zmiana 28.10]” i „[zmiana 30.10]”). Do zabrania ze szkolenia 2.11.2026 i przekazania administratorowi Claude Code w Waszej firmie. Analogia do karty wymagań dla pipeline’u: sekcja testów nie konfiguruje tych rzeczy sama; tu jest lista z uzasadnieniem.

Ustawienia zostały pokazane na szkoleniu na środowisku trenera (organizacja Claude Prosit, laptop trenera, marketplace z publicznego repozytorium na GitHubie). Nie były testowane w sieci ani na Waszych kontach; każdy punkt ma status „zweryfikowane w dokumentacji” albo „do sprawdzenia u Was”. Dokumentacja: https://code.claude.com/docs, stan z 22–23.10.2026.

Cel: każdy tester w sekcji ma po otwarciu repozytorium projektu plugin `qa-standards` z marketplace’u sekcji (`qa-sekcja` w Azure Repos), aktualizowany bez ręcznych kroków, a Claude Code działa przez firmowe proxy. Nazwy `qa-sekcja` i `qa-standards` pochodzą ze szkolenia; u Was nazwa marketplace’u jest do wyboru, a pierwsza wersja pluginu startuje od 0.1.0 [zmiana 28.10].

Przykład kompletnego `managed-settings.json` (punkty 2–4; adres i nazwy do podmiany):

```json
{
  "extraKnownMarketplaces": {
    "qa-sekcja": {
      "source": { "source": "git", "url": "https://dev.azure.com/<org>/<projekt>/_git/claude-plugins" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "qa-standards@qa-sekcja": true
  }
}
```

Jak działa auto-update po wdrożeniu (do oczekiwań użytkowników): po pierwszej wiadomości w sesji Claude Code czeka losowo do 10 minut, potem odświeża marketplace’y z włączonym `autoUpdate` i aktualizuje zainstalowane z nich pluginy. Bez auto-update użytkownik robi `/plugin marketplace update qa-sekcja` i `claude plugin update qa-standards@qa-sekcja`.
